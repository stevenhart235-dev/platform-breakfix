# EKS Milestone 24: immutable lifecycle metadata

M24 adds only the provider-owned identity and temporal facts required by a future AWS-native lifecycle-status observation producer. It does not implement EKS status, verify-clean, resource discovery, broad plan integrity, automatic destruction, or an Operations/foundation contract change. The accepted baseline is `3bdd363bca169310ca10cf72ed4443000fa9cd64`; foundation remains signed `v0.2.0` at `d042fa4e9a3b8ef975554fa56b7c9a4b61547e54`.

## Creation boundary and lifetime

A new lifecycle is planned with:

```powershell
.\scripts\New-EksLabPlan.ps1 -LifetimeHours 4 -TofuPath <path-to-1.11.13-tofu.exe>
.\scripts\Apply-EksLabPlan.ps1 -TofuPath <path-to-1.11.13-tofu.exe>
```

`-LifetimeHours` is a creation-only whole-hour value from 1 through 24; its default is 4. The plan script stores the saved plan below ignored `.runtime/eks/`. If state already contains lifecycle metadata, omitting the parameter reuses the persisted duration and an explicit different value fails closed. Applying the exact saved plan is the minimal metadata binding between plan and provision; M24 does not claim complete AKS-style plan-integrity parity.

The provider-local lifecycle module generates `LabId` with state-backed `random_uuid`, generates `CreatedAt` with state-backed `time_static`, obtains `AccountId` from `aws_caller_identity`, and binds `Region` to the root provider input. It calculates absolute `ExpiresAt` once as `CreatedAt + LifetimeHours`. A `terraform_data` record ignores later input changes, so changes to defaults or configuration cannot advance the clock. A separate guard compares the current account and region with the persisted record before ownership modules can change.

Timestamps use second-precision UTC RFC3339 (`yyyy-MM-ddTHH:mm:ssZ`). Expiration is advisory and never triggers destruction.

## Metadata and tags

Internal metadata schema version `1` has exactly:

- `SchemaVersion`
- `LabId`
- `AccountId`
- `Region`
- `CreatedAt`
- `ExpiresAt`

The complete non-secret AWS tag representation is:

- `platform-breakfix:metadata-schema`
- `platform-breakfix:lab-id`
- `platform-breakfix:account-id`
- `platform-breakfix:region`
- `platform-breakfix:created-at`
- `platform-breakfix:expires-at`
- `platform-breakfix:provider=eks`
- `platform-breakfix:lifecycle=ephemeral`

Existing provider default tags (`Project`, `ManagedBy`, and `Purpose`) remain. Preserved ECR repositories are explicitly outside the ephemeral EKS lifecycle and do not receive lifecycle tags.

## Ownership coverage

| Resource class | Classification | Metadata behavior |
|---|---|---|
| Directly managed VPC and VPC-module network resources | `REQUIRED_FULL_METADATA` | VPC is the earliest durable cloud ownership anchor; module tags propagate lifecycle facts to its owned network graph. |
| Directly managed EKS cluster and EKS-module resources | `REQUIRED_FULL_METADATA` | Cluster and module-managed control-plane, security, IAM, and managed-node-group resources receive the lifecycle tags supported by the pinned module. |
| EBS CSI pod-identity IAM resources | `REQUIRED_FULL_METADATA` | The independently owned identity module receives the complete tag set. |
| Resources generated by AWS and related to the tagged VPC/EKS/node group | `INHERITED_OR_RELATIONSHIP_PROVEN` | Future status may corroborate them from exact owned relationships; M24 does not scan or tag every generated object. |
| AWS-managed transient/generated objects without a supported direct tag surface | `AWS_GENERATED_NOT_TAGGED` | They are not standalone ownership authorities. |
| Preserved ECR repositories and lifecycle policies | `NOT_RELEVANT` | They have a different preservation lifecycle and cannot indicate EKS lab presence. |

A partial provision can leave the VPC/network graph carrying the full identity before the control plane exists. During partial destroy, any surviving directly managed VPC, EKS, or pod-identity resource retains the same tag record naturally; destroy ordering is unchanged. M24 does not claim that this matrix is a verify-clean implementation.

## Existing lifecycle and conflicts

State-backed resources reuse one UUID, creation timestamp, and absolute expiry. Changing `eks_lifetime_hours` after creation is ignored by the immutable record; the supported plan command additionally rejects an explicit conflicting override. Authenticated-account and configured-region mismatches fail before provider ownership modules proceed. The strict local validator rejects missing or unknown fields, malformed UUID/account/region/timestamps, invalid duration, and conflicting expected identity.

OpenTofu state corroborates the record but is not the future cloud authority. `.runtime` contains only an ignored saved plan, and neither it nor the current working directory is required to interpret persisted AWS tags. Metadata contains no credentials, access keys, session tokens, kubeconfig, secrets, raw state, scenario state, health, or mutable provider status.

## Deferred work

`get_lab_status -Provider eks` remains `PROVIDER_UNSUPPORTED`. EKS verify-clean also remains unsupported. A future M25 may add the narrowly bounded AWS observation producer that validates these cloud tags and supplies `State`, `CreatedAt`, and `ExpiresAt` to foundation v0.2.0. It must separately address exact discovery, ambiguity, partial graphs, provider errors, and truthful cleanup evidence without changing this metadata clock.

## Acceptance

Static acceptance covers strict metadata validation, state-backed generation/reuse, immutable timestamps after a configuration change, account/region/LabId conflicts, lifetime bounds, complete tag coverage, the partial-provision anchor, CWD independence, unchanged contracts, and the full platform regression suite. Live acceptance evidence is recorded in the final M24 report after the single authorized EKS lifecycle; no second lifecycle or expiry wait is required.
